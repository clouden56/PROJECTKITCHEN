1. Problem and Objectives

Households routinely discard food that was simply forgotten until it expired, then spend more on groceries or takeaway, and face daily "what can I cook?" decision fatigue. Fridge Recipe Tracker is a command-line kitchen assistant that records fridge and pantry items with expiry dates and asks Google Gemini for a recipe that uses the most urgent items first. The AI output is never trusted blindly: a deterministic rule engine accepts, flags or rejects every suggestion before it reaches the user.

  • Track inventory (name, quantity, unit, location, expiry) in flat JSON files that survive restarts and container rebuilds.
  • Generate recipes with AI under the user's meal type, time limit, allergies and must-include ingredients, using a strict JSON response schema.
  • Decide with business rules: allergen gate (with a synonym map, e.g. dairy → milk, cheese, butter), ≥ 50 % ingredient-match threshold, cook-time limit, must-include check, and a minimum of two inventory items before calling the API.
  • Measure impact: an expiry-priority score (expired/today +40, 1–3 days +30, 4–7 days +15, otherwise +5, capped at 100) and an estimate of grams of food diverted from waste.

2. Architecture

ModuleSingle responsibilityKey procedural functions (all typed; bold = framework API)
io_managerCollect and validate every keystroke and return typed dicts; render every line of output. The only module that calls print() or input().prompt_recipe_generation_criteria, prompt_new_ingredient, prompt_history_filter, display_inventory, display_recipe_card, display_recipe_history

logic_managerApply the business rules to validated AI output and produce a verdict: ACCEPTED, FLAGGED or REJECTED.evaluate, score, route, evaluate_allergen_safety, calculate_ingredient_match_ratio, check_mandatory_ingredients
data_managerLoad, save and query flat JSON files; survive missing, corrupt or unwritable files.save, load, query(filter_fn), load_inventory, save_inventory, quarantine_corrupt_file, query_items_by_expiry
Design conventions. The program is 100 % procedural: there are zero class definitions, and an automated test scans every .py file to enforce this. Layers exchange only plain dict/list values. Failures are returned as values ((success, result, error_message) tuples, defaults or False), so an exception never crosses a layer boundary and the menu loop cannot crash. Diagnostics go to data/app.log through logging, keeping the terminal UI clean.

5. Automated Testing

tests/test_pipeline.py is a procedural test runner: it defines no classes and never contacts the live API. It uses hardcoded sample Gemini responses (tests/sample_ai_responses.py), each a full generateContent envelope as the real API returns it, and substitutes call_api and the keyboard reader with scripted stand-ins. It exits non-zero on any failure, so CI and Docker can gate on it.

6. DevOps: Version Control, CI and Docker

Git workflow

  • Work happens on feature branches (e.g. feature/part1-deliverables) and is merged into main by pull request once CI passes.
  • One logical change per commit, with a descriptive message, e.g. "quarantine corrupt data files and make JSON saves atomic".
  • .env is git-ignored (only .env.example is committed), and the API key is sent in a header, never in a URL.

Docker

  • Dockerfile sits in the repository root and builds on python:3.12-slim with zero third-party packages (standard library only), giving a 43 MB compressed image.
  • /app/data is a volume, so data persists between runs. docker compose run --rm app starts the app; the test service needs no .env.

CI pipeline (.github/workflows/ci.yml)

GitHub Actions runs on every push and on every pull request into main:

  1. Lint & test on Python 3.10 and 3.12: ruff (syntax errors, undefined names), byte-compile, then the full offline suite with an empty API key.
  2. Docker, after step 1 passes: build the image, run the suite inside the container, and smoke-test that the CLI starts and exits cleanly.

A red job blocks the merge, so main always builds, passes its tests and runs in a container.

7. Known Limitations

  • Ingredient matching is lexical (substring and plural stemming), so "coconut milk" matches "milk". Semantic or AI-assisted matching would be more precise.
  • The waste figure is a heuristic: about 100 g per countable unit, with the whole stock of each rescued item counted. Quantities are not decremented after cooking.
  • Pantry staples do not lower the match ratio, but they are still listed as missing and can therefore produce an informational FLAGGED verdict.
